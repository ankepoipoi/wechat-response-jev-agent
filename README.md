# Echo · 聊天洞察

把一段聊天记录粘进来，逐句看清**情绪**和**意图**，看看自己的回复哪里没接住。

底层判断交给 [Jev](https://typesafe.ai/)（TypeSafe 的 System One 判断模型）。
它不生成文字，只从你给的选项里挑一个、或在给定等级上打分 —— 正适合"逐句判断"这种活。

> 这是一个**独立实现**。感谢 [crush-monitor](https://github.com/yzyialy/crush-monitor)
> 提供的产品灵感（尤其是"数字必须由程序算"这条原则），但本仓库的代码、
> 分类体系、评分算法和界面都是另写的，没有复用其源码。

## 它算什么，不算什么

**会算的**：每句的情绪（14 类）与意图（14 类）、对方回复你的平均间隔、
平均字数、主动开口次数、追问比例、你的每条回复的接话质量评级。

**不会算的**：人格诊断、依恋类型、「TA 喜欢你的概率」、情绪操纵建议、
自动发消息。好感度那个数字叫**互动温度**，描述的是这段对话的投入程度，
不是感情结论。

### 一条硬规矩

> **模型只做判断，不碰数字。**

所有展示出来的数值 —— 互动温度、百分比、趋势对比、回复评级 ——
都由 `shared/metrics.ts` 里的纯函数算出。Jev 只回答"这句是什么情绪"
"这条回复接住了吗"这类选择题和打分题。这样做的好处是：结果可复现、
可解释，换模型也不会让数字跳。

互动温度的构成写在界面上：

```
互动温度 = 模型判断分 × 60% + 行为统计分 × 40%
```

## 跑起来

需要 **Node.js ≥ 22.12** 和一个 TypeSafe API Key（[申请](https://console.typesafe.ai/)）。

```bash
# 1. 装依赖
npm install

# 2. 配置 Key
cp .env.example .env
#    编辑 .env，填入 TYPESAFE_API_KEY

# 3. 构建并启动
npm run build
npm start
```

打开 <http://127.0.0.1:3199/> 。改代码时用 `npm run dev`（前端热更新在 5199，
后端 3199，已配好代理）。

跑测试：

```bash
npm test    # 14 个用例，离线可跑，不调用任何模型、不花额度
```

> 请只用 `127.0.0.1` 访问。这个版本没有登录，把 `HOST` 改成 `0.0.0.0`
> 会让同网段的人看到你的聊天记录。

## 怎么用

1. 电脑版微信里多选聊天记录 → 复制 → 粘贴进输入框。
2. 选一个昵称代表"你"。
3. 点「开始分析」。

支持三种粘贴格式，会自动识别：

```text
小洪水                    ← 微信「多选复制」，昵称 / 时间 / 正文各占一行
2026年09月21日 17:18
我们抱一下吧

对方 21:00                ← 简版多行格式
今天加班好累啊

我：辛苦了                 ← 手写速记格式
```

带日期的格式会换算成「距第一条消息的绝对分钟数」，所以跨天对话
（昨晚 23:50 → 今早 08:10）的回复间隔也能算对。

**语音 / 图片 / 表情包**在微信里复制出来只是 `[语音]` 这种占位符。
在占位符后面补一句描述，它才会参与分析（并标注为"你补充的描述"）；
不补就跳过，不参与统计。

```text
对方 21:00
[语音] 她说周末要加班，可能来不了
```

## 最能拉近距离的回复

页面最下方会根据整段聊天，给出 3 条可以直接发出去的回复，并说明每条为什么能拉近距离。

这个功能需要**另接一个生成式大模型** —— Jev 只做判断、不写句子。在 `.env` 里配好即可：

```env
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=你的key
LLM_MODEL=deepseek-chat
```

凡是 OpenAI 兼容的接口都能接（DeepSeek / 通义 / Kimi / 智谱 / OpenAI / 本地 Ollama）。
不配置时该功能会明确提示你去配，其余功能不受影响。

写回复时会把**最近 40 条聊天原文**交给模型，要求它模仿你们自己的说话风格
（用词、语气、长度、标点习惯），而不是套通用话术模板。3 条建议各用不同策略，
比如先接住情绪、顺着对方的梗接话、主动表达感受、推进一件具体的事。

> 这些建议是用来帮你把意思说清楚的，不是话术。觉得不像你平时说话就点「换一批」。

## 保存记录，下次接着聊

聊天可以存成一段一段的记录。**输入框只装新内容，不承载历史** ——
点开某段记录后它是空的，直接粘贴新聊天就会自动接到记录下面并立即保存。

1. 第一次：粘贴聊天 → 起个名字 → 点「保存为新记录」。
2. 以后：在左侧点开这段记录，输入框是空的，**直接粘贴新聊天**就行，
   自动接在下面并保存，不需要再点任何按钮。
3. 也可以先在输入框手动输入，再点「追加到记录」。

**重叠会自动去重**：微信多选复制经常连上次最后几条一起选，重复的部分会
自动去掉，同一条消息不会被分析两遍。

记录存在浏览器 localStorage，可以随时重命名、删除。分析结果也一起存着，
切回去不用重新花额度。

## 目录

```
shared/     前后端共用：类型、聊天解析、纯函数统计（评分算法的全部所在地）
server/     本机后端：Jev 封装、分析编排、Express 入口
src/        前端：React 19 + 自写 CSS，无 UI 框架
```

## 数据与隐私

- 聊天记录与历史基线存在**你这台电脑的浏览器 localStorage**。换浏览器、
  开无痕、清缓存都会丢，也没有跨设备同步。
- API Key 只写在 `.env`，**不下发到浏览器**。
- 分析时会把聊天片段发给 TypeSafe，这是工具工作的前提。

## 注意

好感度是**娱乐性评分**。情绪和意图也只是并列的可能解读，不是定论。
分析别人的聊天之前，请先自己想清楚合不合适 —— 不要用它去监控、
骚扰或操纵任何人。
